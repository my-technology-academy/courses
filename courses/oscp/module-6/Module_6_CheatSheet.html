OSCP: Vulnerability Scanning

6.1 SCANNING THEORY
Process: probe → fingerprint → compare vs known-weakness database
Unauthenticated: outside view, no creds — realistic external simulation
Authenticated: valid creds — inspects patch level/config from inside
Considerations: impact (fragile systems) · timing · noise · accuracy (false pos/neg)
6.2 NESSUS — A SCAN, START TO FINISH
Configure: policy, scope, creds, timing
→
Run scan
→
Triage by severity + plausibility
→
Verify manually before reporting
Components: scan engine (probes) · plugin feed (the checks, must stay current) · policy templates · reporting layer. Every result traces to ONE inspectable plugin — read it before trusting it.
6.3 NMAP NSE vs NESSUS
NessusNmap NSE
CoverageBroad, regularly updated plugin databaseNarrower, but immediate
Best forEstate-wide thorough coverageSpeed, minimal footprint, custom one-off checks
Command(GUI-driven)nmap --script vuln <target>
Most engagements use BOTH — they complement, neither replaces the other. NSE categories: discovery · vuln · auth/brute · safe vs intrusive.
EXAM TRAPS & ACRONYMS
⚠️ A scanner result is a CANDIDATE, not a confirmed finding — always verify manually before reporting
⚠️ Authenticated is not "always better" — unauthenticated is correct when simulating an external attacker with no access
⚠️ NSE does not replace Nessus — it covers far less ground, but is faster and already open from the port scan
⚠️ Severity rating = potential impact IF real, not the scanner's confidence it applies here
⚠️ An outdated plugin feed silently degrades every scan — installation/updates are a real objective, not busywork
