OSCP: Locating Public Exploits

11.1 GETTING STARTED
Risk: untrusted code can exceed scope, damage a target, or compromise your own machine
Rule: analyse before executing — always, regardless of source reputation
Read for: what it connects to, what it writes, and what it assumes about the target
11.2 ONLINE RESOURCES
Differentiate: review standard, visible authorship, currency — not popularity
Risk: altered, backdoored, or non-functional copies circulate
Search operators: narrow results a plain keyword search misses
site:exploit-db.com "apache 2.4.49"
filetype:py "remote code execution" cve-2021
11.3 OFFLINE RESOURCES
Exploit frameworks: bundle many exploits, consistent interface (Module 19 = Metasploit in depth)
SearchSploit: local offline archive, searchable by service/product
Nmap NSE: the Module 6 engine, here testing for/triggering known exploits
searchsploit apache 2.4.49
searchsploit -x 50383
11.4 THE WORKFLOW
1. Enumerate
Precise service, product, version
2. Search
Offline first, then online
3. Analyse
Read before running
4. Execute
Obtain a limited shell
A limited shell is the outcome, not the end — Modules 15/16 escalate from exactly this point. If the exploit fails, Module 12 (Fixing Exploits) is next, not abandonment.
EXAM TRAPS & ACRONYMS
⚠️ Popular ≠ safe — popularity says nothing about review standard or whether the copy matches the original
⚠️ Enumeration must be precise (exact version), not just a service name, before searching for an exploit
⚠️ A limited shell is the terminal outcome here — privilege escalation is a separate objective (Modules 15/16)
⚠️ One matching source is not enough — cross-reference against an independent second source
⚠️ Offline resources can lag the newest exploits; online resources carry sourcing risk — check both
