OSCP: Client-Side Attacks

10.1 TARGET RECONNAISSANCE
Gather: names, roles, projects and routines — Module 5's OSINT, aimed at people
Fingerprint: the client software stack and version
Why: determines both which mechanism applies and how the pretext should read
10.2 EXPLOITING MICROSOFT OFFICE
Variations: more than one Office attack surface exists — confirm before committing
Install Office locally: test payloads against the target's actual version/config first
Word macros: embedded code executed on open/action — legitimate capability, cannot be removed outright
Trigger: a visible security warning the target must actively dismiss
10.3 ABUSING WINDOWS LIBRARY FILES
Library file (.library-ms): points to folder locations; prepare it to reference attacker content
Shortcut (.lnk): crafted to run commands on opening
Key advantage: no macro-style security warning — unfamiliar feature, less scrutiny
CHOOSING A MECHANISM
MechanismWarning behaviourUse when
Word macroVisible security warning, must be dismissedTarget uses Office, macros not blocked by policy
Library file + shortcutNone equivalent — unfamiliar featureMacros disabled by policy, or a quieter delivery is needed
EXAM TRAPS & ACRONYMS
⚠️ Client-side ≠ social engineering only — these are concrete technical mechanisms delivering real code execution
⚠️ One pretext does not fit every target — build it from Objective 10.1's reconnaissance every time
⚠️ Macros disabled by policy does not close off the module — library files/shortcuts have no macro-style warning
⚠️ Test payloads against the target's actual fingerprinted version, not just the newest one
⚠️ Delivered artefacts may not survive on the target — document pretext, mechanism and payload at delivery time
