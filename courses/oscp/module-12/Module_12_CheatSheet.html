OSCP: Fixing Exploits

12.1 FIXING MEMORY CORRUPTION EXPLOITS
Buffer overflow: writing beyond a fixed buffer, overwriting adjacent memory that may control execution
Cross-compiling: build a binary for the target's architecture from a different machine
Modify exploits: adjust offsets/addresses/conditions to match the real target
Scope: high-level theory + repair, not full exploit development
12.2 FIXING WEB EXPLOITS
CategoryTypical symptom
Session stateHard-coded token/cookie no longer matches current session
EncodingPayload characters interpreted differently than expected
Headers/requestMissing/mismatched content type or request method
THE SHARED REPAIR METHOD
1. Isolate
Find exactly where it breaks
2. Compare
Exploit's assumptions vs real target
3. Adjust
One variable at a time
4. Document
What changed, and why
Binary vs Web: memory corruption failures trace to offsets/architecture; web exploit failures trace to session/encoding/headers — same discipline, different checklist.
EXAM TRAPS & ACRONYMS
⚠️ A broken exploit usually means a configuration mismatch, not an absent vulnerability — don't abandon the target
⚠️ This module repairs existing exploits; it does not require writing new memory corruption exploits from scratch
⚠️ Change ONE variable at a time and retest — simultaneous changes hide which one actually mattered
⚠️ Cross-compiling ≠ translating languages — it targets a different architecture/OS with the same source
⚠️ Document the original exploit, the change, and the reason — it's evidence and a reusable reference
