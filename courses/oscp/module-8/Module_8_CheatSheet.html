OSCP: Common Web Application Attacks

8.1 DIRECTORY TRAVERSAL
Root cause: a path parameter trusted to stay inside an intended directory
Absolute path: fully specified from filesystem root
Relative path: specified relative to the current directory — ../ walks up one level
Bypassing filters: encode traversal characters so a naive filter misses them before decoding
GET /view?file=../../../../etc/passwd
8.2 FILE INCLUSION — LFI vs RFI
TypeSource of included content
LFIA file already present on the target's own filesystem
RFIContent served entirely from attacker-controlled infrastructure — most severe
Key distinction from traversal: inclusion causes the referenced content to be executed or rendered, not merely disclosed
PHP wrappers: extend what a file inclusion vulnerability can reach or how it is interpreted (e.g. reading source instead of executing it)
LFI → code execution: a named Module 8 objective — poisoning a log or session file the application then includes
8.3 FILE UPLOAD VULNERABILITIES
Root cause: trusting that an uploaded file's type and content are what they claim
Identify: which extensions/content-types are accepted; client-side vs server-side vs both validation
Exploit: upload crafted content for code execution; try alternate vectors when the first attempt is rejected
Why high-impact: can place executable content directly on the server
8.4 COMMAND INJECTION
Root cause: application input reaches an OS shell and executes as a command
Progression: identify parameter → confirm with an OS command → chain into an interactive channel → leverage for system access
host=8.8.8.8; id
host=8.8.8.8 && whoami
ONE ROOT CAUSE, FOUR ATTACKS
AttackWhat it trusts that it should not
Directory TraversalA path parameter stays within the intended directory
File InclusionA parameter names only a file the application intends to run
File UploadAn uploaded file's declared type matches its actual content
Command InjectionInput reaching a shell contains no unintended commands
EXAM TRAPS & ACRONYMS
⚠️ Traversal discloses a file; inclusion executes or renders it — do not conflate the two
⚠️ RFI is more severe than LFI because the attacker supplies the executed content directly
⚠️ A single filtered traversal/inclusion attempt does not prove the input is sanitised — try alternate encodings and vectors
⚠️ Test every path-like parameter, not only ones obviously named "file" or "path"
⚠️ Client-side upload validation is not a control — always verify server-side enforcement
