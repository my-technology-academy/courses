OSCP: Report Writing for Penetration Testers

4.1 UNDERSTANDING NOTE-TAKING
Deliverables: report = primary; notes/screenshots/output = supporting
Portability: must survive tool/machine/time changes — non-proprietary export
Structure: scope → actions → results → findings extracted
Tool choice: portable export, code/image support, search at scale — not looks
Screenshots: identifier + command + unambiguous result, every time
4.2 THE REPORT, FRONT TO BACK
SectionReaderContains
Executive summaryBoard / non-technicalScope, risk posture, top findings in triad terms, priority actions — no tool names or CVEs
Environment considerationsAll readersTesting window, exclusions, constraints — prevents "scoped" being read as "unconditional"
Technical summarySecurity managerMethodology, tooling, finding counts by severity, chained attack path
Findings + appendicesEngineer / remediatorDescription · Evidence · Impact · Recommendation, per finding; raw logs in appendix
SAME FINDING, TWO READERS
Executive: "An attacker who compromises one staff laptop could read the entire payroll archive. We recommend restricting this access immediately."
Technical: "The FIN-SHARE SMB share grants Domain Users read access to \\fs01\payroll. Restrict the share ACL to the Payroll security group."
WORKFLOW — WRITE IN THIS ORDER, NOT DOCUMENT ORDER
1· Record live: command + output + reasoning, as you go
→
2· Fill the finding template the moment each is confirmed
→
3· Draft the technical summary once all findings exist
→
4· Write the executive summary LAST, Feynman-tested
EXAM TRAPS & ACRONYMS
⚠️ Writing is not separate from the technical work — an unreported compromise has no commercial value
⚠️ Notes written from memory afterwards are reconstructions, not records — detail is already lost
⚠️ A screenshot alone is not evidence — it needs a visible identifier and the command that produced it
⚠️ More technical detail is not always better — it must match the section's actual reader
⚠️ Appendices declutter strong evidence; they never substitute for it
⚠️ Write the executive summary last — summarising requires knowing what was actually found
