OSCP: Antivirus Evasion

13.1 KEY COMPONENTS & OPERATIONS
Known threats: matched reliably against a catalogue
Unknown threats: force heuristic/behavioural judgement
Components: signature database + scanning engine + real-time monitor
EngineBlind spot
Signature-basedAnything sufficiently altered from the catalogued sample
HeuristicCode that looks structurally ordinary
BehaviouralBehaviour that's legitimate until a delayed later stage
13.2 AV EVASION IN PRACTICE
Testing best practice: isolated, locally controlled AV instance — NEVER a public multi-scanner
Manual evasion: alter byte patterns (signature) or restructure behaviour (heuristic/behavioural)
Automated tools: scale evasion — only after manual understanding exists
Always verify: the payload still performs its original function after modification
DIAGNOSING WHICH ENGINE CAUGHT YOU
Detected instantly on delivery, before execution
→ Signature-based matching
Detected only partway through runtime
→ Heuristic or behavioural engine
EXAM TRAPS & ACRONYMS
⚠️ Never test evasion on a public multi-scanner — it can leak the payload to vendors and threat intel feeds
⚠️ AV is a system of components (signature DB, scanning engine, real-time monitor), not one black box
⚠️ Automated evasion tools can fail silently against an engine they weren't tuned for — manual understanding comes first
⚠️ Evasion that breaks the payload's function is not a usable result — always verify function survives
⚠️ Passing an isolated test does not guarantee success on the real target — configurations can differ
