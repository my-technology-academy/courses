OSAI: Attacking Model Context Protocol and Tool Surfaces

7.1 MCP FUNDAMENTALS
MCP (conceptual): standardised interface pattern for tool discovery + invocation
Consumer: the model/agent side seeking tool capability
Provider: the tool-providing side exposing described capability
Discovery phase: consumer learns what tools exist and reads descriptions
Invocation phase: consumer requests execution; result re-enters context
No schema invented: conceptual level only — no version/field-name claims
7.2 TOOL-SURFACE ENUMERATION & ABUSE
Systematic enumeration: maps every reachable tool, not just one
Direct enumeration: what an agent visibly can invoke
Transitive enumeration: tools reachable only through another tool
Excessive agency (LLM06): privilege exceeds task need
Crafted-parameter abuse: legitimate call, unintended target/effect
7.3 MCP-SPECIFIC TRUST WEAKNESSES
Description injection: a tool's own description carries an instruction
Capability over-claiming: description asserts more than the tool does
Compromised provider: a third-party tool-providing side turns malicious
Unverified provenance: no proof a tool is who it claims to be
"Text is code": Module 1 principle extended to the tool-definition layer

EXAM TRAPS & ACRONYMS
⚠️ MCP is a deep dive on Module 3's tool-abuse mechanism, standardised — not an unrelated new topic
⚠️ Enumerating a tool is not the same as confirming it is over-permissioned — compare privilege to task need
⚠️ A tool need not be broken for abuse to be a finding — crafted parameters or a trusted-but-untrue description suffice
⚠️ Tool descriptions are text, read during discovery — treat them as untrusted, exactly like tool output
⚠️ Every finding here belongs to Module 1's agent-and-tool layer — always map back to it in the report
⚠️ OSAI weightings are not published — the exam is a 24-hour practical engagement
