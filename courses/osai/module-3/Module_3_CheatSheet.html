3.1 DIRECT INJECTION & BYPASS
Bypass: deliberately crosses a seam Module 2 already mapped
Override / ignore-instructions: claims priority over the system prompt
Role-play / persona-shift: fictional frame relocates the effective rules
Encoding / obfuscation: disguises intent from pattern-based filters
Multi-turn escalation: intent distributed gradually across turns
Payload splitting: intent distributed across separate inputs/fields
3.2 SYSTEM-PROMPT & CONFIG EXTRACTION
Extraction: deliberate elicitation, not incidental leakage (M2)
Direct ask: lowest effort, often tried first
"Repeat everything above": reframes extraction as formatting
Translation / format-conversion: bypasses direct-request filters
Completion / continuation: model completes a seeded fragment
Why it matters: reveals tool names, rules, attack-surface hints
3.3 TOOL & FUNCTION-CALLING ABUSE
Confused deputy: agent's own privilege is misused via injection
Parameter injection: alters a legitimate tool call's arguments
Forced invocation: triggers a tool call the user never requested
Excessive agency: agent holds more privilege than its task needs
Tool output: a fetched result can itself seed a fresh injection

EXAM TRAPS & ACRONYMS
⚠️ Guardrail bypass is a reproducible finding mapped to a Module 2 seam — not just clever phrasing
⚠️ A leaked system-prompt fragment is reconnaissance value, not the finding itself
⚠️ Tool abuse rarely means the tool is broken — the weakness is trusting an injected instruction to direct it
⚠️ Tool OUTPUT must be treated as untrusted, exactly like user input — it can itself carry an injection
⚠️ Output handling is classic appsec with a new untrusted source — the sink and the fix are unchanged
⚠️ OSAI weightings are not published — the exam is a 24-hour practical engagement
