11.1 SCOPING THE ENGAGEMENT
First action: restate scope and objective before any testing
Scope statement: objective, in-scope, out-of-scope, evidence standard
Scope discipline: every action maps back to an in-scope component
Scope creep: chasing interesting findings outside agreed boundaries
Backlink: M1 Obj 1.4 scoping/RoE; feeds M10 Obj 10.1's objectives input
Graded on: scope discipline is itself part of a successful outcome
11.2 RECON & THREAT MODELING
Recon: map to six layers, enumerate without exploiting, record confidence
Threat modeling: chain paths, score impact/effort, sort, document kill chain
Where they meet: M2 inventory + M11.1 scope → M10's two required inputs
vs jumping to exploitation: disciplined opening outperforms "just start trying"
Failure mode: skipping recon/TM is the most common capstone/exam mistake
Backlink: M2 Obj 2.4 inventory; M10 Obj 10.2–10.4 chaining/priority/kill chain
11.3 EXPLOITATION & POST-EXPLOITATION
Execute: run the kill chain in priority order using M3–M9 techniques
Post-exploitation: extend a foothold until it reaches the scoped objective
Feedback loop: new discoveries re-feed the kill-chain ranking
Breadth vs impact: chained paths to the objective outrank isolated findings
Time discipline: reserve reporting time; re-check priority order, not just the clock
Abandon criteria: a stalled path yields to the next-ranked candidate

EXAM TRAPS & ACRONYMS
⚠️ More findings does not mean a better score — chained impact toward the objective outranks a long unchained list
⚠️ Reporting is not a final-hour task — build it incrementally or it reliably runs out of time
⚠️ Scope is gradable — findings outside agreed boundaries do not count as a successful outcome
⚠️ Skipping threat modeling because a target "looks simple" is the most common capstone/exam failure mode
⚠️ A stalled path should yield to the next-ranked candidate, not consume the remaining window
⚠️ OSAI weightings are not published — the exam is a 24-hour practical engagement, graded end to end
