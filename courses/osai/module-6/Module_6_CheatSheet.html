OSAI: Attacking Embeddings

6.1 EMBEDDING FUNDAMENTALS
Embedding: numeric vector capturing semantic meaning
Similarity search: nearest-neighbour distance, purely geometric
Vector database: Module 5's storage + retrieval stages, reopened
Flow: text → embed model → store → query embed → search
Metrics: cosine similarity, Euclidean distance, dot product
vs keyword match: retrieves meaning, not literal words — but attackable
6.2 EMBEDDING INVERSION
Definition: recovers an approximation of text from its vector alone
Why it matters: exposed vectors ≈ exposed sensitive content
Exposure vectors: debug endpoints, permissive APIs, logs, exports
vs direct exposure: attacker never touches the raw source text
Framework: OWASP LLM08 (mechanism) + LLM02 (disclosure outcome)
Recognise it: vectors reachable under weaker auth than the docs
6.3 EMBEDDING MANIPULATION
Definition: crafted text embeds near a target vector, not the text's meaning
vs corpus poisoning: attacks the vector, not what a human reviews
Origin: adversarial perturbation, carried from predictive-ML evasion (M1 1.1)
Mechanism: target region → craft → ingest → land near → retrieved
Why worse to catch: no keyword signature, review misses it
Framework: OWASP LLM08; ATLAS adversarial-input tactics

EXAM TRAPS & ACRONYMS
⚠️ Embedding inversion recovers an approximation, not an exact reproduction, of the source text — state it precisely
⚠️ Embedding manipulation attacks the vector's position, not the source text a human would review — do not confuse it with corpus poisoning
⚠️ Adversarial perturbation is not new to this module — it is Module 1's predictive-ML evasion concept, redirected at a vector
⚠️ Application-level query scoping provides zero protection if the vector store itself is reachable directly
⚠️ Metadata stored alongside a vector can leak sensitive detail even when the vector and source text are both secure
⚠️ OSAI weightings are not published — the exam is a 24-hour practical engagement
