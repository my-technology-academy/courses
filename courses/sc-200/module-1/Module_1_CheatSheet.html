SC-200: Manage a Security Operations Environment

1.1 AUTOMATION
Email notifications: incidents, actions, threat analytics
Alert notifications: tuning (adjust) / suppression (block) / correlation (group)
MDE: advanced features, rules settings, custom data collection, ASR rules
AIR: auto-investigate + remediate an alert
Attack disruption: intervene mid-attack, break the chain
Device groups: scope permissions + automation levels (per group, not tenant-wide)
1.2 SENTINEL PLATFORM
Roles: Reader (view) → Responder (+manage incidents) → Contributor (+create/edit)
Retention tiers: Analytics (hot) / Data lake (cheap, long-term) / XDR
Workbooks: KQL-driven dashboards, templates customisable
SOC optimization: coverage gaps + unused expensive data
1.4 DETECTIONS
XDR custom detection: promote an Advanced Hunting KQL query to a scheduled rule
Analytics rules: Scheduled / NRT (~1 min) / Threat intelligence / Machine learning
MITRE ATT&CK: maps active rules to tactics → shows coverage gaps
Anomalies: baseline-based, catches novel behaviour; flighting mode to evaluate
1.3 CHOOSING AN INGESTION PATH

EXAM TRAPS & ACRONYMS
⚠️ AIR ≠ attack disruption — AIR handles an alert; disruption breaks an attack in progress
⚠️ Automation level is per device group, not tenant-wide
⚠️ Only suppression stops an alert being raised at all
⚠️ ASR is preventive (blocks technique), not detective (alerts after)
