3.1 GRAPH & INTELLIGENCE
Threat analytics: Microsoft reports + your tenant's exposure + recommended actions
Hunting graphs: visual entity exploration
Blast radius: if this asset is compromised, what else is exposed?
Sentinel Graph: traverse entity relationships across platform data
3.2 SENTINEL PLATFORM HUNTING
Hunting queries: library + bookmarks (preserve result) + livestream (watch for new matches)
KQL jobs in Data lake: scheduled/on-demand queries over cheap long-term tier — NOT interactive
Summary rule tables: pre-aggregate raw data → fast, cheap repeat queries
Notebooks + MCP Server: ML, enrichment, multi-step analysis beyond KQL
CHOOSING A HUNTING SURFACE
Recent XDR telemetry, interactive → Advanced Hunting
Reusable + monitored → Sentinel hunting queries
Months of cheap history → KQL jobs (Data lake)
Repeat queries, huge tables → Summary rule tables
ML / external enrichment → Notebooks
Attack reach & exposure → Hunting graphs / Sentinel Graph
Should be permanent → promote to detection rule
EXAM TRAPS & KEY TERMS
⚠️ An empty result usually means the wrong table, not the absence of the threat
⚠️ The Data lake tier is not queried interactively — historical hunts run as KQL jobs
⚠️ A summary table only holds what was aggregated; dropped detail is unrecoverable from it
⚠️ Hunting ≠ detection — promote valuable hunts into custom detection / analytics rules
⚠️ KQL is tested in Domain 1 too, so it carries more weight than 20–25% suggests
