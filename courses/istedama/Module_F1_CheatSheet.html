1.1 OS STRUCTURE & ADMIN
Kernel mode: unrestricted hardware access — kernel, HAL, drivers
User mode: restricted — Win32 subsystem, services, applications
Local Administrators group: controls install/settings/other-user-data rights
UAC: consent prompt for elevation — a convenience boundary, not user isolation
Driver signing: blocks unsigned kernel-mode code from loading
1.2 BUILT-IN TOOLING
Defender Antivirus: signature + behaviour scanning of files/processes
Windows Firewall: rule-based traffic filtering, per network profile
Event Viewer: Security/System/Application logs — logons, process creation
Services console: what runs in the background, and as which account
Task Scheduler: what runs automatically, and when
1.3 POWERSHELL
Cmdlets: Verb-Noun pattern (Get-Process, Stop-Service)
Pipeline: passes structured .NET objects, not text
Execution policy: Restricted / RemoteSigned / Unrestricted — a guard rail, not a security boundary
WinRM / Remoting: runs commands remotely — a key lateral-movement log source

1.5 ATTACKER PLAYBOOK — WORKFLOWS & BEST PRACTICE
Persistence: registry Run keys · scheduled tasks · auto-start services — remove the artefact, then find the root cause
Privilege escalation: weak service permissions, unquoted service paths take a standard user to SYSTEM
Credential attack: LSASS memory dumping, pass-the-hash — often "living off the land", no malware required
Best practice: restrict LSASS memory read access; review Event Viewer, Services and Task Scheduler routinely
EXAM TRAPS & ACRONYMS
⚠️ UAC is a consent prompt, not isolation between two separate user accounts
⚠️ Execution policy is a guard rail — it does not stop a determined local attacker
⚠️ Share permissions do not apply to a local logon — only NTFS permissions do
⚠️ Antivirus alone will not catch novel or fileless malware — hence EDR
